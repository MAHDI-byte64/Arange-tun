# آرنج‌تان 🎒

**هستهٔ تونل معکوس** · Go · AGPL-3.0 · لینوکس amd64/arm64 · باینری واحد

آرنج‌تان یک هستهٔ **تونل معکوس (Reverse Tunnel)** با کارایی بالاست که کاملاً با
**Go** نوشته شده و برای ست‌آپ سرور **ایران ⇄ خارج (kharej)** ساخته شده. یک باینری
واحد و مستقل است با یک **CLI تعاملی** و یک **داشبورد وب** امن — یعنی همه‌چیز را با
ترمینال یا بدون ترمینال می‌توانی مدیریت کنی.

> 📖 English: **[README.md](README.md)**

---

## چطور کار می‌کند

تونل معکوس جهت همیشگی را برعکس می‌کند: **کلاینت همیشه به بیرون dial می‌کند**، پس
ماشین پشت آن نیازی به هیچ پورت ورودی باز ندارد.

</div>

<div dir="ltr">

```
end user ──▶ forwarded port (Iran server) ──[ one transport ]──▶ kharej client ──▶ real service
                       ▲                                                │
                       └─────────────── tunnel dialed by the client ────┘
```

</div>

<div dir="rtl">

- **سرور ایران** (نقش: *server*) نقطهٔ ورود است. پورت‌های forward‌شده را نمایش
  می‌دهد؛ کاربران داخلی به **آی‌پی ایران** وصل می‌شوند که برایشان سریع و در دسترس است.
- **سرور خارج / kharej** (نقش: *client*) به سرور ایران dial می‌کند و ترافیک را به
  **سرویس واقعی** (پنل VPN، وب‌اپ، …) می‌رساند.
- ترافیکی که وارد یک پورت forward‌شده در سمت ایران می‌شود، از طریق **یک ترنسپورت**
  به سمت خارج برده و به سرویس آنجا تحویل داده می‌شود.

همیشه اول **سرور ایران** را بساز، بعد کلاینت خارج — کلاینت به آدرس ایران و توکنی که
سرور می‌سازد نیاز دارد.

## نصب

یک دستور، به‌صورت root روی VPS. هیچ نسخهٔ آمادهٔ (release) منتشرشده‌ای وجود ندارد —
نصب‌کننده آرنج‌تان را **از روی سورس می‌سازد**: سورس فعلی این رپو را داخل
`/root/Arange-tun` دانلود می‌کند، اگر ماشین Go به‌روز نداشته باشد خودش Go را نصب
می‌کند، باینری را کامپایل می‌کند و منو را باز می‌کند:

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mahdi-byte64/Arange-tun/main/install.sh)
```

<div dir="rtl">

منو را هر وقت خواستی دوباره باز کن با:

</div>

```bash
sudo arange-tun
```

<div dir="rtl">

همه‌چیز در یک چیدمان مرتب است: سورس و بیلد در `/root/Arange-tun`، بکاپ‌ها در
`/root/Arange-tun/backups`، و کانفیگ تونل‌ها در `/etc/arange-tun`.

سرور باید به **github.com** (برای سورس) و پراکسی‌های ماژول Go دسترسی داشته باشد
(اول مستقیم، بعد میرورهای سازگار با ایران). اگر از قبل یک کلون از رپو داری، اجرای
`sudo bash install.sh` داخل آن، همان سورس محلی را می‌سازد و چیزی دانلود نمی‌کند.

**آپدیت** — همان دستور تک‌خطی را دوباره اجرا کن. آخرین سورس را می‌گیرد و باینری را
سرجایش دوباره می‌سازد؛ تونل‌های تو در `/etc/arange-tun` دست‌نخورده می‌مانند، پس
بعدش با `sudo arange-tun` → *Restart ALL* ری‌استارتشان کن.

## شروع سریع

اول نقش‌ها را درست بگیر — این تنها چیزی است که مردم رویش اشتباه می‌کنند:

</div>

<div dir="ltr">

| Role | Where it runs | How to create it | What it does |
|------|---------------|------------------|--------------|
| **Server** | Iran server (entry point) | *Setup Server* | Exposes the ports; users connect to the Iran IP. |
| **Client** | Abroad / kharej (origin) | *Setup Client* | Dials the Iran server and forwards to the real service. |

</div>

<div dir="rtl">

### از طریق CLI

**۱) روی سرور ایران — تونل Server را بساز**

</div>

```bash
sudo arange-tun   →  1. Setup Server
```

<div dir="rtl">

خانوادهٔ ترنسپورت (TCP / UDP / WebSocket) و سپس نوع آن، پورت تونل و پورت‌های
نمایش‌داده‌شده را انتخاب کن، **توکن ۶۴ کاراکتری** پیشنهادی را بپذیر (Enter بزن) و یک
پیش‌تنظیم کارایی انتخاب کن — **Turbo** پیش‌فرض پیشنهادی است. توکن را کپی کن؛ روی
کلاینت لازمش داری.

**۲) روی سرور خارج (kharej) — تونل Client را بساز**

</div>

```bash
sudo arange-tun   →  2. Setup Client
```

<div dir="rtl">

**آی‌پی سرور ایران**، پورت تونل و **همان توکن** را وارد کن. تمام.

### از طریق داشبورد وب

پنل را باز کن (پورت 7777، پایین‌تر ببین)، روی **New tunnel** بزن، سمت (سرور یا
کلاینت) را انتخاب کن، همان فیلدها را پر کن و ثبت کن — تونل بلافاصله نوشته، فعال و
اجرا می‌شود، دقیقاً مثل CLI. برای تونل سرور که توکنش را خالی بگذاری، یک توکن ۶۴
کاراکتری ساخته و یک‌بار نمایش داده می‌شود تا برای کلاینت کپی‌اش کنی.

---

## داشبورد وب

یک داشبورد امن روی **پورت 7777** که با ظاهر CLI هماهنگ است. لینک و کد ورود در CLI
زیر **Web Panel** نشان داده می‌شود (که پورت پنل، گواهی و رمز هم همان‌جاست). اول پورت
را روی فایروال باز کن، مثلاً `sudo ufw allow 7777`.

داشبورد می‌تواند:

- **ساخت تونل** — سرور یا کلاینت، همهٔ ترنسپورت‌ها و پیش‌تنظیم‌ها، گزینه‌های TLS
  (self-signed / Let's Encrypt / فایل‌های موجود)، و یک بخش تنظیمات پیشرفتهٔ اختیاری
  با همان کلیدهای دستی CLI.
- **ری‌استارت یا حذف** یک تونل از دیالوگ Details آن.
- **مانیتورینگ** زندهٔ CPU / RAM / دیسک / ترافیک، وضعیت هر تونل، پینگ واقعی و
  لاگ‌ها — همراه با متریک‌های هر تونل و بلندمدت.
- مدیریت **بکاپ**، **تنظیم تلگرام** و **رمز پنل** در بخش Settings.

هر عملیات ساخت / ری‌استارت / حذف، دقیقاً همان کاری را می‌کند که CLI می‌کند (فایل
کانفیگ، یونیت systemd، استارت/استاپ سرویس)، پس تونلی که از پنل ساخته یا حذف شود با
تونلی که از ترمینال ساخته یا حذف شود یکسان است.

## انواع تونل — کدام را انتخاب کنی

آرنج‌تان هشت نوع تونل را با یک چرخهٔ یکسان (ساخت ← اجرا ← مانیتور ← ویرایش ← حذف)
مدیریت می‌کند. در پنل، دکمهٔ **New tunnel** آن‌ها را به دو خانواده تقسیم می‌کند:
**معکوس** (فوروارد پورت) و **مستقیم** (خروج VPN). هر نوع قبل از فرمش یک راهنمای کوتاه
دارد.

- **Backhaul** — معکوس · 🇮🇷 ایران=سرور، 🌍 خارج=کلاینت · وقتی پیش‌فرضِ منعطف با
  ترنسپورت‌های متنوع می‌خواهی.
- **frp** — معکوس · 🇮🇷 ایران=سرور، 🌍 خارج=کلاینت · ریورس‌پراکسی ساده و سریع با
  obfuscation.
- **Rathole v2** — معکوس · 🇮🇷 ایران=سرور، 🌍 خارج=کلاینت · کانال دادهٔ مجزا و pooled
  برای تأخیر کم و پایدار.
- **Packet** — معکوس (برعکس) · 🌍 خارج=سرور، 🇮🇷 ایران=کلاینت · وقتی DPI/فایروال
  سخت‌گیر است — زیر لایهٔ کرنل پنهان می‌شود.
- **WireGuard** — مستقیم (خروج VPN) · 🌍 خارج=سرور، 🇮🇷 ایران=کلاینت (SOCKS5) · خروج
  کامل VPN، با obfuscation آمنزیا.
- **SSH** — مستقیم (خروج VPN) · 🇮🇷 فقط کلاینتِ ایران · خروج سریع فقط با یک لاگین SSH.
- **Hedioum** — مستقیم (خروج VPN) · 🌍 خارج=foreign، 🇮🇷 ایران=hub (SOCKS5) · خروجِ
  SOCKS5 با استخر پویا که خود را شبیه SSH/TLS/ایمیل نشان می‌دهد و خودمقیاس است.

### Backhaul — موتور داخلی

تونل معکوس پیش‌فرض و منعطف‌ترین: نه ترنسپورت روی TCP/UDP/WebSocket، connection
pooling، پیش‌تنظیم‌ها و گزینه‌های DPI.

- **🇮🇷 ایران (سرور):** Setup Server → ترنسپورت + پیش‌تنظیم، پورت تونل و پورت‌های
  نمایش‌داده‌شده را بگذار و **توکن ۶۴ کاراکتری** را کپی کن.
- **🌍 خارج (کلاینت):** Setup Client → آی‌پی ایران، پورت تونل و **همان توکن**.

### frp — ریورس‌پراکسی داخلی

پروتکل خودِ frp (هندشیک توکن + استریم‌های مالتی‌پلکس)، کامپایل‌شده، بدون باینری
خارجی. در نوع **TCP** یا **UDP**، با انتخاب **DPI obfuscation**: *Stealth (نویز)* —
شبه‌تصادفی و بدون فینگرپرینت — یا *TLS (uTLS)* — شبیه HTTPS معمولی، با گواهی خودامضا
یا **Let's Encrypt واقعی**.

- 🇮🇷 ایران=سرور (پورت‌ها را نمایش می‌دهد) · 🌍 خارج=کلاینت (توکن و obfuscation یکسان
  روی هر دو سمت).

### Rathole v2 — ریورس‌پراکسی pooled

یک پورت وفادار از Rathole در Go: یک کانال کنترل + یک **مجموعه از کانال‌های دادهٔ
مجزا** که تأخیر را زیر بار زیاد کم و پایدار نگه می‌دارد. همان انواع TCP/UDP و همان
گزینهٔ obfuscation مثل frp.

- 🇮🇷 ایران=سرور · 🌍 خارج=کلاینت.

### Packet — پکت خام، زیر لایهٔ کرنل

قوی‌ترین دور زدن DPI. با libpcap **پکت‌های TCP خامِ ساختگی** می‌گیرد و تزریق می‌کند و
یک ترنسپورت KCP رمزنگاری‌شده را **زیر لایهٔ TCP/IP کرنل** حمل می‌کند — پس DPI و
فایروال‌های stateful که کانکشن‌های خود کرنل را ردیابی می‌کنند اصلاً آن را نمی‌بینند
(حتی `ufw deny` روی پورت بی‌اثر است).

- **توپولوژی برعکس:** 🌍 **خارج=سرور** (اکسیت‌نود — گوش می‌دهد و یک کلید مشترک می‌سازد؛
  سرویس واقعی را همین‌جا اجرا کن) · 🇮🇷 **ایران=کلاینت** (پورت‌ها را نمایش می‌دهد و dial
  می‌کند). هر پورت نمایش‌داده‌شده ۱‑به‑۱ به `127.0.0.1:<port>` روی سرور می‌رود.
- **نیازها:** **root** و **libpcap** روی هر دو سمت (خودکار نصب می‌شود)، **فقط لینوکس**،
  و یک **پورت بالای غیراستاندارد** (هرگز ۸۰/۴۴۳). اینترفیس، آی‌پی محلی، MAC گیت‌وی و
  قوانین فایروال همه خودکار تشخیص/اعمال می‌شوند.

### WireGuard — خروج VPN

یک خروج کامل VPN، نه تونل معکوس. سمت خارج یک اکسیت‌نود کرنلی وایرگارد است؛ سمت ایران
وایرگارد را **در فضای کاربر** بالا می‌آورد و یک **پراکسی SOCKS5** محلی باز می‌کند که
ترافیکش از تونل خارج می‌شود.

- **🌍 خارج (سرور):** یک کانفیگ وایرگارد می‌سازد — به کلاینت کپی کن.
- **🇮🇷 ایران (کلاینت):** **هر** کانفیگ وایرگاردی را paste کن (سمت سرور، WARP،
  سرویس‌دهنده یا خودت)، یک پورت SOCKS5 انتخاب کن و اوت‌باند پنل را به
  `127.0.0.1:<port>` وصل کن. کانفیگ‌های **AmneziaWG** هم کار می‌کنند — obfuscation
  آن‌ها بلاک‌های مبتنی بر فینگرپرینت وایرگارد را دور می‌زند.

### SSH — SOCKS5 روی SSH

ساده‌ترین خروج، **فقط کلاینت** — روی سرور جز یک لاگین SSH چیزی لازم نیست. آرنج‌تان به
یک سرور خارج لاگین می‌کند و یک **SOCKS5** محلی باز می‌کند که ترافیکش از آن بیرون
می‌رود، و اگر ارتباط قطع شود خودکار وصل می‌شود.

- **🇮🇷 ایران (کلاینت):** آی‌پی/دامنه، پورت، یوزرنیم و پسورد سرور و یک پورت SOCKS5
  محلی را وارد کن؛ در پنل یک اوت‌باند SOCKS به `127.0.0.1:<port>` اضافه کن.
- امنیتش عمداً سبک است (لاگین با پسورد، کلید میزبان در اولین اتصال مورد اعتماد) — برای
  راحتی از آن استفاده کن، نه به‌عنوان یک کانال سخت‌گیرانه.

### Hedioum — SOCKS5 روی پایپ‌های استتارشده و استخر پویا

یک خروج دو-نودی که **SOCKS5 را روی یک استخر خودمقیاس از پایپ‌های استتارشده** حمل
می‌کند. هر پایپ خود را شبیه یک پروتکل واقعی — **SSH، TLS، SMTP یا IMAP** — نشان می‌دهد،
با ChaCha20-Poly1305 رمز می‌شود و پهنای‌باندش را نوسان می‌دهد تا الگوهای DPI را محو
کند. نود خارج برای هر کاوشِ بدون توکن یک صفحهٔ **تقلبی** (Apache یا DirectAdmin) نشان
می‌دهد تا مثل یک سرور معمولی دیده شود.

- **🌍 خارج (foreign):** یک **استتار** و یک پورت گوش‌دادن انتخاب کن، در صورت تمایل یک
  دامنه برای گواهی واقعی **Let's Encrypt** (ACME)؛ یک **توکن** مشترک می‌سازد.
- **🇮🇷 ایران (hub):** آن را با **همان استتار** و **توکن** به آی‌پی/پورت خارج اشاره بده و
  یک پورت SOCKS5 محلی انتخاب کن؛ در پنل یک اوت‌باند SOCKS به `127.0.0.1:<port>` اضافه
  کن. استخر خودش با بار زیاد و کم می‌شود.

> موتور Hedioum **با اجازهٔ نویسنده** و با ذکر منبع از
> [Hedioum Pool Tunnel](https://github.com/hedioum/Hedioum-Pool-Tunnel) ساختهٔ
> **hedioum** vendor شده است؛ همهٔ اعتبارِ طراحی از آنِ اوست — فایل
> [`internal/hedioum/engine/NOTICE.md`](internal/hedioum/engine/NOTICE.md) را ببین.

## ترنسپورت‌ها

نه ترنسپورت روی TCP، UDP و WebSocket، به‌علاوهٔ یک گزینهٔ آزمایشی روی ICMP، همه با
connection pooling:

</div>

<div dir="ltr">

| Family | Variants | Notes |
|--------|----------|-------|
| **TCP** | TCP, TCP Mux, TCP + Stealth | *Stealth* wraps TCP in a Noise layer with **no fingerprint** — random-looking bytes with nothing for DPI to match. Best under heavy filtering. |
| **UDP** | UDP, UDP + KCP | *KCP* adds reliable delivery with **forward error correction**, repairing loss without waiting for a retransmit. |
| **WebSocket** | WS, WS Mux, WSS, WSS Mux | *WSS* uses TLS with a real Chrome fingerprint and a Let's Encrypt (or self-signed) certificate; a **decoy site** answers non-tunnel probes so the server looks like a normal HTTPS website. |
| **Experimental** | xDi (ICMP) · IP Spoofing | ‏xDi تونل را داخل پکت‌های پینگ می‌برد؛ IP Spoofing تونل KCP را داخل پکت‌های خام IPv4 با **سورس جعلی** حمل می‌کند (پروفایل‌های udp/icmp/tcp، استخر سورس چرخشی، ابهام‌سازی ضدDPI و حالت پایپ WireGuard). هر دو فقط لینوکس و نیازمند root. |

</div>

<div dir="rtl">

هر ترنسپورت در **[docs/transports.md](docs/transports.md)** توضیح داده شده. اگر
سرور خارج DPI-filter شده باشد، معمولاً **TCP + Stealth** یا **WSS** تونل را رد
می‌کنند؛ بلاک شدن آی‌پی در لایهٔ شبکه یا یک خروجی «کثیف» موضوع آی‌پی تمیز / CDN است —
ببین **[docs/filtered-or-dirty-ip.md](docs/filtered-or-dirty-ip.md)**.

## امکانات

**کارایی**

- چهار پیش‌تنظیم — **Balance**، **Turbo** (پیشنهادی) و **Aggressive** برای
  لینک‌های تأخیرمحور (بازی)، به‌علاوهٔ **Throughput** روی خانوادهٔ KCP برای یک
  دانلود سریع تک‌جریانی — که پول‌ها، بافرهای سوکت، پنجره‌های دریافت، FEC و
  تنظیمات کرنل (BBR + fq) را تنظیم می‌کنند.
- **Link Test** مسیر را می‌سنجد (تأخیر، jitter، loss) و ترنسپورت مناسب را پیشنهاد
  می‌دهد و تایمرهای liveness را از رفت‌وبرگشت واقعی تو مشتق می‌کند.
- **Optimize** تنظیمات کرنل/شبکه را خودش اعمال می‌کند (BBR + fq، سقف بافر سوکت،
  محدودیت file-descriptor).

**پایداری**

- **failover خودکار** به آدرس‌های پشتیبان سرور وقتی آدرس اصلی فیلتر شود، یا **توزیع
  بار** روی همهٔ آن‌ها هم‌زمان.
- **watchdog خودترمیم** تونل قطع‌شده را ظرف ~۱ دقیقه از سرویس خودش ری‌استارت می‌کند —
  مانیتورینگ حتی با پنل وبِ متوقف هم ادامه دارد.
- **بازگشت خودکار (rollback)** — آپدیت‌ها و ویرایش‌ها اگر تونل بالا نیاید، خودشان
  برمی‌گردند.
- سرویس‌های **مدیریت‌شده با systemd** که از ریبوت و بستن ترمینال جان سالم به‌در می‌برند.

**امنیت**

- **توکن روی ترنسپورت رمزنگاری‌شده هیچ‌وقت به‌صورت متن‌ساده منتقل نمی‌شود.** Stealth و
  KCP کلیدهایشان را بدون ارسال توکن از آن مشتق می‌کنند؛ WSS / WSS Mux اعتبار را به
  نشست TLS گره می‌زنند. (TCP / TCP Mux / WS ساده آن را همان‌طور می‌فرستند — روی مسیر
  نامطمئن از ترنسپورت رمزنگاری‌شده استفاده کن.)
- **PROXY Protocol v2** آی‌پی واقعی هر کاربر را forward می‌کند، پس محدودیت‌های
  per-user در پنل پشت تونل کار می‌کنند.
- **محدودیت‌های هر تونل** روی تعداد اتصال هم‌زمان و روی throughput.
- داشبورد محافظت‌شده با ورود.

**مدیریت**

- **CLI تعاملی** برای ست‌آپ، ویرایش پورت‌ها / ترنسپورت / پیش‌تنظیم، کنترل هر تونل،
  لاگ زنده و وضعیت — هر گزینه خودش را توضیح می‌دهد.
- **ست‌آپ آدرسی که می‌دهی را بررسی می‌کند**، دربارهٔ CDN جلوی سرور یا رکورد AAAA که
  تونل را روی IPv6 می‌فرستد هشدار می‌دهد.
- **CDN edge** — کلاینت می‌تواند به‌جای origin از طریق یک CDN edge (مثل Cloudflare)
  به سرور برسد، پس آی‌پی خود سرور لو نمی‌رود.
- **لاگ JSON** (`log_format = "json"`) برای log collectorها؛ لاگ خوانا پیش‌فرض می‌ماند.
- **Auto-refresh** — ری‌استارت همهٔ تونل‌ها هر N ساعت.

**مانیتورینگ**

- **داشبورد وب (پورت 7777)** — ساخت، ری‌استارت، حذف و تماشای تونل‌ها، با متریک‌های
  زندهٔ سیستم و هر تونل (بالاتر توضیح داده شد).
- **متریک‌ها** — ترافیک و اتصال‌ها روی هر ترنسپورت و، روی KCP، retransmit، loss و
  پکت‌های ترمیم‌شده با FEC. مجموع‌ها بین ری‌استارت‌ها حفظ می‌شوند.
- **Health Check** — سرور، پنل و هر تونل را تست می‌کند و زیر هر مشکل یک راه‌حل چاپ
  می‌کند.

**آپدیت و بکاپ**

- **آپدیت** — دستور تک‌خطی نصب را دوباره اجرا کن تا آخرین سورس گرفته و باینری سرجایش
  دوباره ساخته شود. تونل‌ها و تنظیماتت در `/etc/arange-tun` دست‌نخورده می‌مانند.
- **بکاپ** — هر تونل، رمز پنل، تنظیمات تلگرام، گواهی‌های TLS و زمان‌بندی در یک
  `.tar.gz` قابل‌حمل، از CLI، پنل وب یا ربات.

**تلگرام**

- **هشدارها** وقتی CPU / حافظه / دیسک از حد بگذرد، یا تونلی قطع یا وصل شود — هرکدام با
  یک پیام بازیابی.
- وضعیت، سیستم و بکاپ روی درخواست، به‌صورت دکمه یا دستور.
- تلگرام را **از طریق یک تونل** می‌گیرد، پس از داخل ایران که تلگرام بلاک است کار
  می‌کند، خودش تونل را انتخاب می‌کند و وقتی یکی بیفتد به دیگری می‌رود.

## چیدمان فایل‌ها

</div>

<div dir="ltr">

| Path | What |
|------|------|
| `/usr/local/bin/arange-tun` | the binary |
| `/etc/arange-tun/` | per-tunnel TOML configs and runtime state |
| `/root/Arange-tun/` | the source and build |
| `/root/Arange-tun/backups/` | configuration backups |
| `arange-tun-<name>.service` | one systemd unit per tunnel |

یونیت‌های systemd اجرا می‌کنند)؛ `arange-tun --webui` پنل وب را اجرا می‌کند؛
`arange-tun -v` نسخه را چاپ می‌کند.

## ساخت از سورس

به **Go 1.24+**، یک **کامپایلر C** و **هدرهای توسعهٔ libpcap** نیاز دارد
(`libpcap-dev` در دبیان/اوبونتو، `libpcap-devel` در RHEL/فدورا). باینری با cgo
ساخته می‌شود چون تونل **Packet** یک موتور پکت خام (libpcap) درون خود دارد؛ بقیهٔ
کد خالص‌Go است. اسکریپت نصب این‌ها را خودکار آماده می‌کند. از داخل یک کلون از رپو:

</div>

```bash
CGO_ENABLED=1 go build -o arange-tun .   # ساخت باینری
make release                             # کراس-بیلد لینوکس amd64 + arm64 در ./release
go test ./...                            # اجرای تست‌ها (تست‌های e2e ترافیک واقعی می‌برند)
```

<div dir="rtl">

**نیازمندی‌های اجرا:** لینوکس (amd64 یا arm64)، root، و systemd. تونل Packet
علاوه بر این به libpcap در زمان اجرا نیاز دارد (خودکار نصب می‌شود).
